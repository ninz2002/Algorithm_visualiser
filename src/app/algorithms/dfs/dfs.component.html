Depth-First Search

Dive deep before you go wide.

What is it?

DFS explores a graph by going as deep as possible down each branch before backtracking. Think of navigating a maze — you keep going forward until you hit a dead end, then backtrack and try a different path.

When to use it?

  • Cycle detection — Find cycles in a directed or undirected graph
  • Topological sorting — Order tasks with dependencies
  • Connected components — Identify isolated subgraphs
  • Pathfinding in mazes — Explore one path fully before trying another
Key Insight

DFS uses a stack — either explicitly or via recursion's call stack. The stack naturally enforces the "go deep first" behavior. When you pop a node, you push all its unvisited neighbors, and the last one pushed gets explored next.

Performance Analysis

Understanding how Depth-First Search performs

Time Complexity

O(V + E)

What does this mean?

DFS visits every vertex (V) exactly once and examines every edge (E) at least once.

Why O(V + E)?

Each node is pushed and popped from the stack once — O(V). For each node we inspect all neighbors — totaling O(E) across all nodes.

Real-world example

Exploring a building: visit every room (V) and walk every corridor (E) exactly once.

Space Complexity

O(V)

What does this mean?

In the worst case the stack can hold all vertices — e.g. a straight-line path graph.

Why O(V)?

  • The visited set — up to V nodes
  • The stack — up to V nodes worst case
Real-world example

A "rooms still to visit" list — at most all rooms are on it before you start crossing them off.
